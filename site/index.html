Process means the role may encode or prepare a transaction. Approve, Post, and Admin identify controlled actions reserved for the assigned role.

Member Classification

Cluster / Group is controlled by the agreed TASETEMCO classifications: REGULAR MEMBERS CAPTURE, REGULAR MEMBERS NON CAPTURE, RETIREES, REGULAR MEMBERS LGU, COMMUNITY A MEMBERS, and COMMUNITY B MEMBERS. Manual forms use a dropdown. Excel/CSV imports accept matching values case-insensitively, normalize them, and flag unknown classifications before staging.

Membership and Balances

Staff can process member applications, import validated profiles, apply approved opening balances, and review member statements with source evidence.

Loans

Loan staff can prepare applications, record credit decisions, generate amortization schedules, release funded loans, and collect scheduled installments.

Teller and Accounting

Teller transactions move through cash count, Bookkeeper review, posting, and official batch closing with linked journals and variance controls.

Reports and Oversight

Authorized users can review cash position, subsidiary balances, reconciliation, trial balance, financial condition, user access, and audit evidence.

Operating flow

Core Cooperative Workflows

Member Application

  1. Membership Officer encodes application.
  2. Required Initial Share Capital is reviewed.
  3. Application is submitted for approval.
  4. System Administrator approves membership.
  5. Teller collects initial share capital, membership fee, and savings.
  6. Admin or Membership Officer maintains member profile master data.
  7. Cluster / Group is selected from the approved TASETEMCO classification list.
  8. Admin or Membership Officer can preview mapped Excel/CSV member imports.
  9. CSV imports normalize matching cluster/group values and flag unknown classifications.
  10. Admin or Membership Officer can stage mapped import rows for review.
  11. System blocks duplicate initial member payments for the same member.
  12. System blocks reused cash-in OR/reference numbers.
  13. Transaction remains in teller batch until accounting posting.

Teller Transaction

  1. Teller selects active member account.
  2. Member statement shows share capital, savings, and posting status.
  3. Teller chooses one transaction type in the workspace.
  4. Share capital contribution is available after onboarding.
  5. Selected transaction is encoded and validated.
  6. System blocks reused OR or voucher reference numbers.
  7. Receipt is issued.
  8. Cash in, cash out, net cash, and transaction counts are summarized.
  9. Teller submits actual cash counted and system computes variance.
  10. Bookkeeper records a variance note when the cash count has non-zero variance.
  11. Bookkeeper marks the submitted teller batch as reviewed.
  12. System allows posting only after the batch is reviewed.
  13. Bookkeeper posts the reviewed teller batch in one action.
  14. Bookkeeper confirms official close after its transactions are posted.
  15. System keeps read-only batch history for audit review.
  16. Batch history rows can be opened for cash count, transaction, and journal details.
  17. Reports summarize daily cash position from teller batch evidence.
  18. Reports summarize member subsidiary balances for share capital and savings.
  19. Reports compare subsidiary activity against GL control accounts.
  20. Transaction stays in teller batch until posting.

Loan Application

  1. Loan Officer selects an active member and active loan product.
  2. Loan Officer selects the internal collateral type: PDC or ATM Cards.
  3. System validates requested principal and term against product limits.
  4. Loan Officer saves and may edit their own Draft.
  5. Collateral type supports management review only and is not included in the printed loan application form.
  6. Loan Officer can use Prepare Form to save editable paper-form fields such as address, spouse, manual co-maker, promissory note number, place signed, and routing notes.
  7. Loan Officer can print a pre-filled paper loan application form from Prepare Form; the amortization schedule remains printed from saved computation as the attachment.
  8. Loan Officer submits the Draft, making it read-only.
  9. System Administrator records assessment notes and a loan decision.
  10. Returned applications go back to Draft for Loan Officer revision.
  11. Approved and Rejected applications retain immutable decision evidence.
  12. Loan Officer previews the schedule with 2.5% monthly diminishing interest.
  13. Most products deduct the 4.5% service fee from principal before release.
  14. Petty Cash Loan is limited to PHP 1,000 to PHP 2,000 and has no service fee.
  15. Salary, Educational, and Appliance loans also deduct insurance, CBU, and savings retention.
  16. CBU can be removed only when the member is fully subscribed.
  17. Loan Officer saves the approved amortization schedule.
  18. Saved computations can print a member loan breakdown before teller release.
  19. Saved computations move to For Release without moving cash.
  20. Bookkeeper prepares Teller funding and Manager approves it.
  21. Assigned Teller acknowledges funding into the Open batch.
  22. Teller confirms the unique release voucher and exact net cash proceeds.
  23. Released proceeds enter the Open teller batch as cash-out evidence.
  24. Bookkeeper reviews the batch and records any required variance note.
  25. Posting creates the balanced loan release journal and linked evidence.
  26. Dashboard Loan Portfolio Watch summarizes overdue installments and installments due within 7 days.
  27. Detailed borrower names in Loan Portfolio Watch are visible only to management, loan, accounting, audit, and executive roles.

Loan Product Deductions

  1. Emergency Loan is fixed at 6 months with a 4.5% service fee.
  2. Petty Cash Loan is fixed at 1 month, supports PHP 1,000 to PHP 2,000, and has no service fee.
  3. Salary Loan supports PHP 10,000 to PHP 350,000.
  4. Educational Loan supports PHP 5,000 to PHP 10,000.
  5. Appliance Loan supports PHP 5,000 to PHP 100,000.
  6. Salary, Educational, and Appliance loans deduct 1.5% insurance, 2% CBU, and 1% savings retention.
  7. Service fee and insurance post to other income; CBU posts to share capital and savings retention posts to member savings.

Ledger Posting

  1. Teller payment remains in Teller Batch status.
  2. Bookkeeper reviews the supporting transaction.
  3. Loan releases debit Loans Receivable for principal.
  4. Cash is credited only for net proceeds released to the member.
  5. Loan collections may be partial, full, or advance receipts.
  6. Collection receipts apply first to interest, then principal, with the split visible before posting.
  7. Deducted service fee, insurance, CBU, and savings retention are posted to their mapped accounts.
  8. Opening balance imports are previewed separately before any cutover balance write exists.
  9. Reports are generated from posted ledger entries.

Data protection

Demonstration Data Safety

The System Administrator can download a backup and restore the demonstration records when testing input needs to be cleared. Reset requires typed confirmation and preserves a pre-reset backup for recovery.

Database maintenance and deployment steps are handled by the implementation team. Staff users work through the application screens and do not need access to database tools or hosting settings.

Loan Document Form v1 adds the loan_document_forms table. The implementation team should run npm run pg:migrate before deploying that app build; if the app is deployed first, Prepare Form shows a migration message.

The System Administrator can create demonstration staff users, assign roles and default screens, and deactivate non-admin accounts. Demonstration accounts use a shared temporary password until individual password management is introduced. The Auditor / Compliance Officer can review usernames, roles, default screens, and account status through a read-only User / Security directory without password, maintenance, backup, or reset access.

Loan Portfolio Watch contains sensitive borrower collection information, so portfolio-wide overdue borrower details are hidden from Teller/Cashier and Membership Officer dashboards.

TASETEMCO Workflow Guide

A staff onboarding reference for cooperative users, access levels, transaction flow, approvals, and ledger-driven reporting.

Access control

Process means the role may encode or prepare a transaction. Approve, Post, and Admin identify controlled actions reserved for the assigned role.

Member Classification

Cluster / Group is controlled by the agreed TASETEMCO classifications: REGULAR MEMBERS CAPTURE, REGULAR MEMBERS NON CAPTURE, RETIREES, REGULAR MEMBERS LGU, COMMUNITY A MEMBERS, and COMMUNITY B MEMBERS. Manual forms use a dropdown. Excel/CSV imports accept matching values case-insensitively, normalize them, and flag unknown classifications before staging.

Membership and Balances

Staff can process member applications, import validated profiles, apply approved opening balances, and review member statements with source evidence.

Loans

Loan staff prepare applications and amortization schedules; System Administrator records the audited decision; Teller releases funded loans and collects installments.

Teller and Accounting

Teller transactions move through cash count, Bookkeeper review, posting, and official batch closing with linked journals and variance controls.

Reports and Oversight

Authorized users can review cash position, subsidiary balances, reconciliation, trial balance, financial condition, user access, and audit evidence.

Operating flow

Core Cooperative Workflows

Member Application

  1. Membership Officer encodes the application, including gender, searchable Philippine ID type, and ID number.
  2. Required Initial Share Capital is reviewed.
  3. Application is submitted for approval.
  4. System Administrator or General Manager approves membership.
  5. Teller collects initial share capital, membership fee, and savings.
  6. Admin or Membership Officer maintains member profile master data, including gender and identification details.
  7. Admin, Membership Officer, or Loan Officer maintains previous / existing loan rows for setup balances.
  8. Previous / existing loan rows capture label, application date, outstanding balance, and notes without creating cash movement.
  9. Cluster / Group is selected from the approved TASETEMCO classification list.
  10. Admin or Membership Officer can preview mapped Excel/CSV member imports.
  11. CSV imports normalize matching cluster/group values and flag unknown classifications.
  12. Admin or Membership Officer can stage mapped import rows for review.
  13. System blocks duplicate initial member payments for the same member.
  14. System blocks reused cash-in OR/reference numbers.
  15. Transaction remains in teller batch until accounting posting.

Teller Transaction

  1. Teller searches and selects an active member account.
  2. The member autocomplete matches name, number, cluster, or contact and supports Up/Down, Enter, Tab, and Escape.
  3. Member statement shows share capital, savings, and posting status.
  4. Teller chooses one transaction type in the workspace.
  5. Share capital contribution is available after onboarding.
  6. Selected transaction is encoded and validated.
  7. System blocks reused OR or voucher reference numbers.
  8. Receipt is issued.
  9. Cash in, cash out, net cash, and transaction counts are summarized.
  10. Teller submits actual cash counted and system computes variance.
  11. Bookkeeper records a variance note when the cash count has non-zero variance.
  12. Bookkeeper marks the submitted teller batch as reviewed.
  13. System allows posting only after the batch is reviewed.
  14. Bookkeeper posts the reviewed teller batch in one action.
  15. Bookkeeper confirms official close after its transactions are posted.
  16. System keeps read-only batch history for audit review.
  17. Batch history rows can be opened for cash count, transaction, and journal details.
  18. Reports summarize daily cash position from teller batch evidence.
  19. Reports summarize member subsidiary balances for share capital and savings.
  20. Reports compare subsidiary activity against GL control accounts.
  21. Transaction stays in teller batch until posting.

Daily Cost-Center Payables

  1. System Administrator maintains cost centers and their SUMMO mapping: Canteen A/B to Canteen, Water Refilling Station to WRS, and G-mar Commercial to G-mar Capital.
  2. Teller chooses a cost center and actual transaction date; skipped days may be entered later.
  3. Teller searches members and enters amount, source reference, and optional remarks in a multi-member Draft.
  4. Drafts have no payable effect and only the creating Teller may edit them.
  5. Only Teller/Cashier finalizes the batch into immutable member payable movements; Admin configures centers and reviews activity.
  6. Each movement snapshots its SUMMO mapping so later configuration changes cannot rewrite history.
  7. An incorrect charge is corrected by a linked negative reversal with a mandatory reason, then a new Draft.
  8. Manager, Bookkeeper, and Auditor reconcile by date, center, status, or member and drill down to source and audit evidence.
  9. A member filter recalculates only that member's portion of a mixed-member batch.

Monthly Member Contributions

  1. Teller selects the contribution month and enters a unique official receipt/reference.
  2. Each Active member row may contain TFEA, CBU, Secured Savings, or any combination.
  3. Saving a Draft has no cash, member balance, payable, journal, or SUMMO effect.
  4. The creating Teller adds the Draft to the current Open teller batch.
  5. The full contribution total becomes part of expected cashier cash.
  6. Teller submits the cash count and Bookkeeper reviews the batch.
  7. Reviewed-batch posting debits Cash on Hand and credits TFEA Payable, Share Capital, and Secured Savings Payable.
  8. Posting increases member CBU/share capital and fills TFEA, CBU, and Secured Savings in SUMMO.
  9. Posted Secured Savings increases a separate member balance and never changes regular savings.
  10. Teller may withdraw posted Secured Savings less pending secured withdrawals.
  11. The withdrawal is teller cash-out; posting debits Secured Savings Payable, credits Cash on Hand, and reduces only the secured balance.
  12. Monthly Contributions never aggregate into member payables.

Daily Remittance

  1. Admin configures source name, reporting group, optional cost center, income account, display order, and status.
  2. Teller opens a fixed grid containing every Active configured source; Admin and oversight users see a read-only screen.
  3. Teller enters the operational Remittance Date, actual Cash Received Date, unique receipt/reference, positive amounts, and optional remarks.
  4. Zero-value rows are not saved. A Draft has no cash, journal, member-payable, or SUMMO effect.
  5. The creating Teller adds the Draft to the Open teller batch, including its total in expected cashier cash.
  6. After cash count and Bookkeeper review, posting debits Cash on Hand and credits each source's snapshotted income account.
  7. Canteen A/B remain separate; WRS and Water Bottle A/B retain detail while rolling up under WRS.
  8. POS, GCASH, and LOADER are standalone, non-cost-center sources that post to 4080 - Other Operating Income.
  9. Piso WiFi, printing and photocopy, water vendo, catering, and additional configured sources retain their reporting definitions.

Daily Disbursement

  1. Admin configures category name, reporting group, optional cost center, 5xxx expense account, display order, and status.
  2. Standard categories are Canteen A, Canteen B, WRS, Building and renovations, Travel, Water, Light, Wifi, SSS, Pag-ibig, Philhealth, and Other expenses.
  3. Other expenses is deliberately displayed as the last Daily Disbursement item.
  4. Teller enters a backdateable Disbursement Date, actual Cash Disbursed Date, unique voucher/reference, positive amounts, and optional remarks.
  5. Zero-value rows are not saved. A Draft has no cash or journal effect.
  6. The creating Teller adds the Draft to the Open teller batch, including its total in cash-out and expected ending cash.
  7. Teller and Admin monitor the same active batch ID, so their transaction counts and rows reconcile.
  8. After cash count and Bookkeeper review, posting debits the snapshotted expense accounts and credits 1010 - Cash on Hand.
  9. Canteen A/B retain C1/C2 and WRS retains WRS; all other standard categories belong to cooperative operations.
  10. Admin may configure additional categories as new expenses are identified.

Loan Application

  1. Loan Officer selects an active member and active loan product.
  2. Loan Officer selects the internal collateral type: PDC, ATM Cards, or Payroll.
  3. System validates requested principal and term against product limits.
  4. Loan Officer saves and may edit their own Draft.
  5. Collateral type supports management review only and is not included in the printed loan application form.
  6. Loan Officer can use Prepare Form to save editable paper-form fields such as address, spouse, manual co-maker, promissory note number, place signed, and routing notes.
  7. The application snapshots manual previous-loan balance, outstanding system loans, CBU, regular savings, and separate secured savings as of the application date.
  8. Loan Officer can print a pre-filled paper loan packet on 8.5 x 13 paper.
  9. Loan Officer submits the Draft, making it read-only.
  10. System Administrator records assessment notes and a loan decision.
  11. Returned applications go back to Draft for Loan Officer revision.
  12. Approved and Rejected applications retain immutable decision evidence.
  13. Loan Officer previews the schedule with 2.5% monthly diminishing interest.
  14. Most products deduct the 4.5% service fee from principal before release.
  15. Petty Cash Loan is limited to PHP 1,000 to PHP 2,000 and has no service fee.
  16. Salary, Educational, and Appliance loans also deduct insurance, CBU, and savings retention.
  17. CBU can be removed only when the member is fully subscribed.
  18. Loan Officer saves the approved amortization schedule.
  19. From the Releases tab, View Schedule opens the installments and Print Breakdown can print a member loan breakdown.
  20. The four-page packet contains application and approval, proceeds and acknowledgement, promissory-note appendix, and amortization schedule.
  21. Saved computations move to For Release without moving cash.
  22. Bookkeeper prepares Teller funding and Manager approves it.
  23. Assigned Teller acknowledges funding into the Open batch.
  24. Teller confirms the unique release voucher and exact net cash proceeds.
  25. Released proceeds enter the Open teller batch as cash-out evidence.
  26. Bookkeeper reviews the batch and records any required variance note.
  27. Posting creates the balanced loan release journal and linked evidence.
  28. Dashboard Loan Portfolio Watch summarizes overdue installments and installments due within 7 days.
  29. Detailed borrower names in Loan Portfolio Watch are visible only to management, loan, accounting, audit, and executive roles.

Loan Product Deductions

  1. Emergency Loan is fixed at 6 months with a 4.5% service fee.
  2. Petty Cash Loan is fixed at 1 month, supports PHP 1,000 to PHP 2,000, and has no service fee.
  3. Salary Loan supports PHP 10,000 to PHP 350,000.
  4. Educational Loan supports PHP 5,000 to PHP 10,000.
  5. Appliance Loan supports PHP 5,000 to PHP 100,000.
  6. LBP Loan uses the Appliance Loan rules, is non-revolving, and supports principal up to PHP 500,000.
  7. Salary, Educational, and Appliance loans deduct 1.5% insurance, 2% CBU, and 1% savings retention.
  8. Service fee and insurance post to other income; CBU posts to share capital and savings retention posts to member savings.

Ledger Posting

  1. Teller payment remains in Teller Batch status.
  2. Bookkeeper reviews the supporting transaction.
  3. Loan releases debit Loans Receivable for principal.
  4. Cash is credited only for net proceeds released to the member.
  5. Loan collections may be partial, full, or advance receipts.
  6. Advance receipts allocate from the oldest unpaid installment through future installments, applying each installment's interest before principal.
  7. The preview lists every installment that will become Paid or Partial; the original amortization schedule is not recomputed.
  8. Deducted service fee, insurance, CBU, and savings retention are posted to their mapped accounts.
  9. Opening balance imports are staged and finalized separately with linked cutover journals.
  10. Reports are generated from posted ledger entries.

SUMMO Monthly Report

  1. Finalized Canteen A/B purchases automatically supply Canteen, Water Refilling Station purchases supply WRS, G-mar Commercial purchases supply G-mar Capital, and posted Monthly Contributions supply TFEA, CBU, and Secured Savings.
  2. Bookkeeper uses the standard XLSX only for categories not yet captured by system transactions.
  3. System validates reporting month, member, category, amount, reference, and reversals.
  4. Bookkeeper reviews and finalizes a valid import batch; it does not post journals.
  5. System combines finalized system and imported movements with scheduled loan dues, posted cash collections, and carried balances.
  6. Posted LBP schedules fill the LBP due date and amount in columns F and G; new external imports no longer accept LBP.
  7. A legacy imported LBP amount overlapping a native LBP schedule blocks locking to prevent double counting.
  8. Pending cost-center Drafts, unsupported mappings, or duplicate system/Excel sources block locking.
  9. System applies effective-dated interest rules, rounds components to cents, and flags unmapped loans.
  10. Bookkeeper refreshes and reconciles source totals plus movement, batch, and member drill-down.
  11. The screen may be filtered to one member without changing the complete snapshot or XLSX export.
  12. General Manager locks the month; Auditor and Board retain read-only access.
  13. Export produces printable Regular Capture, Loan Details, and Audit sheets.
  14. Generate Preview fills the client-format workbook from current finalized system movements before locking.
  15. Download Locked Version produces the official client-format workbook only after the month is locked.
  16. The first-sheet pilot fills member names plus G-mar Capital, Canteen, WRS, TFEA, CBU, and Secured Savings from system transactions. Excel-import values are not copied into these cells.
  17. The workbook keeps its protected 2% G-mar interest formula and calculates the interest from the filled G-mar amount.
  18. The exact six sheets, formulas, yellow manual cells, headers, merged cells, formatting, and five future cluster sheets remain unchanged.
  19. Generation stops when template safeguards fail or the Active Regular Capture roster exceeds the current 67-row capacity.
  20. A locked month blocks affected new, edited, finalized, and reversed cost-center activity.
  21. Reopening a locked month also unlocks every later locked SUMMO month for chronological regeneration.
  22. Only REGULAR MEMBERS CAPTURE SUMMO is implemented; other cluster transactions remain recorded for future cluster reports.

Data protection

Demonstration Data Safety

The System Administrator can download a backup and restore the demonstration records when testing input needs to be cleared. Reset requires typed confirmation and preserves a pre-reset backup for recovery.

Database maintenance and deployment steps are handled by the implementation team. Staff users work through the application screens and do not need access to database tools or hosting settings.

Loan Document Form v1 adds the loan_document_forms table. The implementation team should run npm run pg:migrate before deploying that app build; if the app is deployed first, Prepare Form shows a migration message.

The System Administrator can create demonstration staff users, assign roles and default screens, and deactivate non-admin accounts. Demonstration accounts use a shared temporary password until individual password management is introduced. The Auditor / Compliance Officer can review usernames, roles, default screens, and account status through a read-only User / Security directory without password, maintenance, backup, or reset access.

Loan Portfolio Watch contains sensitive borrower collection information, so portfolio-wide overdue borrower details are hidden from Teller/Cashier and Membership Officer dashboards.

Accounting output

Financial and Operational Reports

TASETEMCO treats the general ledger as the source of financial statements. SUMMO is a separate operational monthly receivables report. It combines finalized system transactions with validated Excel inputs for categories not yet captured in the application. It can also fill the cooperative's exact six-sheet workbook without replacing its formulas or manual cells.
